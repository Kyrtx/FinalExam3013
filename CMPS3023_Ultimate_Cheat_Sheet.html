▌ 1 · Floating-Point ▌
① Decimal → IEEE 754 Hex

Given: A decimal number. Find: 32-bit IEEE 754 hex.

  1. Integer → binary. Divide by 2 repeatedly, remainders bottom→top. (58 → 111010)
  2. Fraction → binary. Multiply by 2 repeatedly, integer parts top→down. (.25 → .01)
  3. Combine. −58.25 = −111010.01₂
  4. Normalize. Shift to get 1.xxxx × 2ⁿ. Count shifts = exponent. (1.1101001 × 2⁵)
  5. Sign bit: positive = 0, negative = 1
  6. Biased exponent = exponent + 127, convert to 8-bit binary. (5+127=132=10000100)
  7. Fraction field = digits after leading 1, padded to 23 bits. (1101001→11010010000000000000000)
  8. Assemble [S][E 8bits][F 23bits]. Group into nibbles → hex digits.
Verify: S=1 → hex starts with 8-F. S=0 → hex starts with 0-7. If your answer violates this, recheck.
② Hex → Decimal
  1. Hex → 32-bit binary. Each hex digit = 4 bits.
  2. Split: bit31 = S, bits[30:23] = E, bits[22:0] = F
  3. Actual exponent = E (decimal) − 127
  4. Mantissa = 1.F (prepend the implicit 1)
  5. Shift binary point right by exponent (if positive) or left (if negative)
  6. Binary → decimal. Integer part: add powers of 2. Fraction: 2⁻¹=0.5, 2⁻²=0.25, 2⁻³=0.125…
  7. Apply sign.

③ Floating-Point Addition (8-Step Method)
  1. Extract S, E, F from both numbers
  2. Prepend leading 1 → mantissa. (F=.101 → M=1.101)
  3. Compare exponents → find difference
  4. Shift SMALLER exponent's mantissa RIGHT by the difference
  5. Add mantissas (subtract if signs differ)
  6. Normalize to 1.xxxx form, adjust exponent
  7. Round to 23 fraction bits
  8. Reassemble S + (exp+127) + fraction → hex
Step 4: Always shift the SMALLER exponent's mantissa. Never shift the bigger one.
Step 8: Don't forget to ADD 127 back to the exponent before assembling.

▌ 2 · K-Maps ▌
⑤ Minimize a Boolean Function
  1. Draw K-map grid with Gray code ordering (00, 01, 11, 10).
  2. Fill in 1s from truth table. Mark don't cares as X.
  3. Circle groups using the 5 rules (below).
  4. Read each circle: variables constant within the circle stay; variables that change are dropped. Constant=1 → uncomplemented. Constant=0 → complemented.
  5. OR all terms.

The 5 Circling Rules

  1. Every 1 must be in at least one circle
  2. Circle size = power of 2 (1, 2, 4, 8, 16)
  3. Each circle as LARGE as possible
  4. Circles can WRAP around edges
  5. Circle X's ONLY if it makes a group bigger

⑩ Sequential Logic Patterns (Flip-Flops / Registers)

D Flip-Flop (basic)

process(clk) begin
    if clk'event and clk='1' then
        q <= d;
    end if;
end process;

With Async Reset

process(clk, reset) begin
    if reset = '1' then
        q <= "0000";
    elsif clk'event and clk='1' then
        q <= d;
    end if;
end process;

With Enable

process(clk) begin
    if rising_edge(clk) then
        if enable = '1' then
            q <= d;
        end if;
    end if;
end process;
Reset goes FIRST (before elsif). Enable goes INSIDE the clock check. This order matters for synthesis.
⑪ Structural VHDL (Component + Port Map)
architecture struct of top is
    -- Step 1: declare the component
    component adder
        port(a, b : in  std_logic_vector(3 downto 0);
             s   : out std_logic_vector(3 downto 0));
    end component;
    -- Step 2: declare internal wires
    signal w : std_logic_vector(3 downto 0);
begin
    -- Step 3: instantiate
    u1: adder port map(x, y, w);  -- x→a, y→b, w←s
    u2: adder port map(w, z, out1); -- chain output
end;
Port map connects BY POSITION. First signal → first port, second → second, etc.
⑫ ROM in VHDL (for FSMD Controller)
library IEEE;
use IEEE.STD_LOGIC_1164.ALL;
use IEEE.NUMERIC_STD.ALL;

entity GCDROM is
    port( clk  : in  std_logic;
          addr : in  std_logic_vector(6 downto 0);
          data : out std_logic_vector(8 downto 0));
end;

architecture test of GCDROM is
    type rom_t is array(0 to 127)
        of std_logic_vector(8 downto 0);
    constant ROM : rom_t := (
        0 => "000000001",
        1 => "000000010",
        -- ... fill from state table
        others => "000000000");
begin
    process(clk) begin
        if rising_edge(clk) then
            data <= ROM(to_integer(unsigned(addr)));
        end if;
    end process;
end;

ROM address = state bits & input bits concatenated. ROM data = next state bits & control signals concatenated.

▌ 4 · FSM ▌
⑭ Design a Moore FSM (Complete Procedure)
  1. Identify inputs and outputs.
  2. Draw state transition diagram. Circles = states (outputs INSIDE). Arrows = transitions (labeled with input conditions). Self-loops where state stays same.
  3. Write state transition table. Current State | Inputs → Next State.
  4. Choose state encoding. N states → ⌈log₂N⌉ bits. (4 states → 2 bits, 5-8 states → 3 bits.)
  5. Rewrite table with binary encodings.
  6. Write SEPARATE output table. Columns: state bits → output bits. (Moore: no inputs in output table.)
  7. Derive Boolean equations for each S' bit and each output bit. (Use K-maps if 3+ variables.)
  8. Draw schematic: Inputs → [Next State Logic] → [State Register + CLK + Reset] → [Output Logic] → Outputs. State bits feed back.
⑮ Design a Mealy FSM

Same 8 steps as Moore, with these differences:

  • State diagram: outputs on arrows as input/output, NOT inside circles.
  • Step 6: NO separate output table. Outputs are extra columns IN the transition table (they depend on state + input).
  • Output logic receives state bits AND input bits.
Moore vs. Mealy on the exam: If outputs labeled inside states → Moore. If on arrows → Mealy. Mealy can react faster (output changes mid-cycle) but is more complex.
⑯ Transition Table → Boolean Equation (How To)

For EACH output column (S'₁, S'₀, Lₐ₁, etc.):

  1. Find every row where that column = 1.
  2. Write a product term: include each variable (uncomplemented if 1, complemented if 0, skip if X).
  3. OR all product terms together.
  4. Simplify (K-map, Boolean algebra, or inspection).

Example from Traffic Light (S'₀ column)

S'₀ = 1 in rows: (S₁=0, S₀=0, Tₐ=0) and (S₁=1, S₀=0, T_B=0)

→ S'₀ = S̅₁·S̅₀·T̅ₐ + S₁·S̅₀·T̅_B

▌ 5 · FSMD ▌
⑲ Algorithm → FSMD (The 3 Templates)

Template A — Assignment: One state per line

x = expr;  →  [ state N: x = expr ] → next state

Template B — While Loop: Condition state + loop-back

while(cond) {   →  ┌→[C: cond?]── !cond ──→ done
   body;           │      │ cond
}                  │      ↓
                   │  [body states]
                   │      ↓
                   └──[J: jump back to C]

Template C — If/Else: Branch + join

if (c1) s1;     →  [C: check]
else s2;              /     \
                  c1 /       \ !c1
                  [s1]      [s2]
                     \       /
                    [J: join] → next
Rule: Each assignment = its own state. Only combine during optimization (card ㉑).
⑳ Build the Datapath (4 Sub-Steps)
  1. Register for every declared variable → int x, y, z → registers x, y, z
  2. Functional unit for every operation → x-1 → subtractor, z+y → adder, x!=0 → comparator
  3. MUX where a register loads from multiple sources:
    — x loads from x_i (line 3) OR subtractor (line 6) → add 2:1 MUX before x
    — z loads from 0 (line 2) OR adder (line 7) → add 2:1 MUX before z
    — y only loads from y_i → no MUX needed
  4. Name control signals:
    — Load enables (one per register): ldx, ldy, ldz, ldd_o
    — MUX selects (one per MUX): selx, selz
    — Status signals (comparator → controller): x_eq_0
㉑ Controller Signal Mapping

For each FSMD state, translate the action into control signals:

FSMD SaysController SetsWhy
z = 0selz=0, ldz=1MUX picks the 0 input, z loads
x = x_iselx=0, ldx=1MUX picks x_i, x loads
y = y_ildy=1y has no MUX, just load
x = x − 1selx=1, ldx=1MUX picks subtractor output, x loads
z = z + yselz=1, ldz=1MUX picks adder output, z loads

Then build the full state table: [current state + inputs] → [next state + all control signals]

Don't care rule: If a register isn't being loaded (ld=0), its select signal is X (don't care).
㉒ Optimize the FSMD (Reduce States)
  1. Eliminate constant-transition states. while(1) always loops → remove it.
  2. Merge state + jump state if nothing happens between them.
  3. Merge independent assignments. Writing to DIFFERENT registers, no dependency → one state. (x=x_i and y=y_i → merge.)
  4. Merge consecutive condition checks. If one leads directly to another.
  5. Eliminate jump-only states. Redirect arrows from source states directly.
CANNOT merge: Assignments that depend on each other (z=x+1 then w=z+2) or write to the SAME register.

GCD example: 13 states → 5 states after all optimizations.

㉓ ROM-Based Controller Implementation
  1. ROM address = [current state bits] concatenated with [input/status bits]
  2. ROM data = [next state bits] concatenated with [control signal bits]
  3. ROM size = 2^(address width) entries × (data width) bits
  4. Fill ROM from state table. For don't-care inputs, duplicate the row for both 0 and 1.

GCD Example Sizing

4 state bits + 3 inputs (go_i, x_neq_y, x_lt_y) = 7-bit address → 128 entries.
4 next-state bits + 5 control bits (x_sel, y_sel, x_ld, y_ld, d_ld) = 9-bit data.
ROM = 128 × 9.

▌ Common Pitfalls ▌
⚠ Floating-Point Mistakes
  • Bias is 127 (not 128). biased = actual + 127.
  • Forgetting the implicit leading 1 when converting hex → decimal.
  • Shifting the WRONG mantissa during addition (shift the smaller exponent's mantissa).
  • Forgetting to re-add 127 when reassembling after addition.
  • Getting confused: after normalizing to 1.xxxxx × 2ⁿ, store ONLY the xxxxx part (NOT the leading 1).
⚠ K-Map Mistakes
  • Wrong row/column order. MUST be Gray code: 00, 01, 11, 10.
  • Making circles that aren't powers of 2 (no circles of 3, 5, 6, 7).
  • Not making circles as large as possible.
  • Circling don't cares unnecessarily (only circle X if it makes a group bigger).
  • Forgetting that K-maps WRAP around edges (left↔right, top↔bottom).
⚠ VHDL Mistakes
  • Using = instead of <=. Signal assignment is ALWAYS <=.
  • Forgetting library IEEE; use IEEE.STD_Logic_1164.all;.
  • Single quotes for single bit: '0'. Double quotes for vectors: "0101". Mixing them up.
  • Declaring signals AFTER begin (they must go BEFORE begin).
  • Sensitivity list wrong in process: for flip-flop use (clk) or (clk, reset).
  • Port map: signals matched BY POSITION. Wrong order = wrong connections.
⚠ FSM Mistakes
  • Mixing up Moore and Mealy. Moore: outputs INSIDE circles. Mealy: outputs ON arrows.
  • For Moore, putting inputs in the output table (outputs depend ONLY on state).
  • Forgetting to feed state register outputs BACK to next state logic.
  • Forgetting the Reset arrow pointing to the initial state.
  • Not accounting for every input combination in every state (incomplete table).
⚠ FSMD Mistakes
  • Merging assignments that depend on each other — they MUST be separate states.
  • Forgetting that comparator outputs (status signals) go FROM datapath TO controller.
  • Setting a load enable to 1 when the register should NOT update (all ld=0 in idle states).
  • Forgetting MUX select is don't care (X) when the load enable is 0.
  • ROM address: forgetting to include ALL input/status bits, not just state bits.
  • ROM: not duplicating rows for don't care inputs (ROM needs an entry for every address).
