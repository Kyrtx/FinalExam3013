Floating-Point Representation

1.1 Fixed-Point Numbers (Foundation)

Fixed-point uses a set number of integer bits and fraction bits. The binary point is implied, not stored.

Converting decimal fractions to binary:

  • Integer part: divide by 2 repeatedly, collect remainders bottom-to-top
  • Fraction part: multiply by 2 repeatedly, collect integer parts top-to-bottom
Lecture Example Represent 7.5 in 8-bit fixed-point (4 integer, 4 fraction):
7 = 0111₂  |  0.5 = .1₂  →  Combined: 0111.1000 → stored as 01111000
Signed Fixed-Point (Two's Complement) Represent −7.5:
1. Start with +7.5 → 01111000
2. Invert all bits → 10000111
3. Add 1 to LSB → 10001000

1.2 IEEE 754 Single-Precision (32-bit) Format

1Sign
8 bitsExponent
23 bitsFraction
  • Sign bit: 0 = positive, 1 = negative
  • Bias = 127
  • Biased exponent = actual exponent + 127
  • Implicit leading 1: The mantissa always starts with 1.xxxx, so only the fraction after the decimal is stored

1.3 Step-by-Step: Decimal → IEEE 754 Hex

Professor's Example — Convert −58.25 to IEEE 754 Hex

Step 1 — Convert to binary:
58 = 111010₂  |  0.25 = .01₂ → −58.25 = −111010.01₂

Step 2 — Normalize:
111010.01 = 1.1101001 × 2⁵

Step 3 — Fill in each field:
Sign = 1 (negative)
Exponent = 5 + 127 = 132 = 10000100₂
Fraction = 11010010000000000000000

Step 4 — Assemble:
1 | 10000100 | 11010010000000000000000
Nibbles: 1100 0010 0110 1001 0000 0000 0000 0000
→ 0xC2690000

1.4 Floating-Point Addition (Professor's 8-Step Method)

Lecture Example — Add 0x3FC00000 + 0x40500000

1. Extract exponent and fraction bits:
N1: S=0, E=127, F=.1  |  N2: S=0, E=128, F=.101

2. Prepend leading 1:
N1: 1.1  |  N2: 1.101

3. Compare exponents:
127 − 128 = −1, so shift N1 right by 1

4. Shift smaller mantissa:
N1 → 0.11 (× 2¹)

5. Add mantissas:
0.11 + 1.101 = 10.011 (× 2¹)

6. Normalize & adjust exponent:
10.011 × 2¹ = 1.0011 × 2²

7. Round: Fits in 23 bits, no rounding needed

8. Assemble:
S=0, E = 2 + 127 = 129 = 10000001₂, F = 00110…
→ 0x40980000

Karnaugh Maps (K-Maps)

2.1 Key Definitions

  • Complement: variable with a bar (A̅, B̅, C̅)
  • Literal: a variable or its complement (A, A̅, B, B̅)
  • Implicant: product of literals (AB̅C)
  • Prime implicant: implicant corresponding to the largest possible circle in a K-map

2.2 K-Map Rules (Professor's Rules)

Memorize These 5 Rules
  1. Every 1 in the K-map must be circled at least once
  2. Each circle must span a power of 2 (1, 2, 4, 8…) squares in each direction
  3. Each circle must be as large as possible
  4. A circle may wrap around the edges of the K-map
  5. A "don't care" (X) is circled only if it helps minimize the equation

2.3 Reading the Answer from Circles

After circling, for each circle: include only the variables that do NOT change within that circle. If the variable is always 1 in the circle, include it uncomplemented. If always 0, include it complemented.

2.4 Three-Variable K-Map Example

Important: Column ordering is 00, 01, 11, 10 (Gray code — only one bit changes between adjacent columns).

       AB
C\AB | 00 | 01 | 11 | 10 |
  0  |  0 |  1 |  1 |  0 |
  1  |  0 |  1 |  0 |  0 |

Circle (01,0) and (11,0) → B C̅
Circle (01,0) and (01,1) → A̅ B

Result: Y = A̅B + BC̅

2.5 Four-Variable K-Map (Seven-Segment Display, Segment "a")

b1b0\b3b2 | 00 | 01 | 11 | 10 |
    00     |  1 |  0 |  1 |  1 |
    01     |  0 |  1 |  1 |  1 |
    11     |  0 |  0 |  0 |  0 |
    10     |  1 |  0 |  0 |  1 |

a = b̅₃b₁ + b₃b̅₂b̅₁ + b̅₃b₂b₀ + b̅₂b̅₀

2.6 K-Maps with Don't Cares

When input combinations can never occur (e.g., BCD values 10–15), mark those cells as X. Circle them as 1's only when doing so makes a group larger.

b1b0\b3b2 | 00 | 01 | 11 | 10 |
    00     |  1 |  0 |  X |  1 |
    01     |  0 |  1 |  X |  1 |
    11     |  1 |  1 |  X |  X |
    10     |  1 |  1 |  X |  X |

a = b₁ + b₃ + b̅₂b̅₀ + b₂b₀

2.7 Five-Variable K-Map (Integer Square Root)

For 5 variables, use rows = last 2 variables, columns = first 3 variables (Gray code). Professor's results:

  • Y₂ = A
  • Y₁ = A̅C + A̅B
  • Y₀ = BE + BD + BC + A̅C̅E + A̅C̅D

VHDL

3.1 Basic Structure

Every VHDL design has two parts: the entity (interface) and the architecture (behavior).

library IEEE;
use IEEE.STD_Logic_1164.all;

-- ENTITY: declares inputs/outputs
entity example is
    port(a, b, c: in STD_LOGIC;
         y:      out STD_LOGIC);
end;

-- ARCHITECTURE: defines the behavior
architecture synth of example is
    signal p, g: STD_LOGIC;  -- internal signals
begin
    y <= a and b;
end;

3.2 Data Types

  • STD_LOGIC — single bit ('0', '1', 'Z', 'X', etc.)
  • STD_LOGIC_VECTOR (N downto 0) — bus of N+1 bits

3.3 Operators

Bitwise: and, or, xor, nand, nor, not

3.4 Conditional Assignment (Multiplexer)

-- 2:1 MUX
y <= d0 when s = '0' else d1;

3.5 Vector Elements & Bit Slicing

-- Access individual bits
y <= a(7) and a(6) and a(5) and a(4) and
     a(3) and a(2) and a(1) and a(0);

-- Slice a range
b <= a(7 downto 4);  -- upper 4 bits

3.6 Internal Signals

architecture synth of fulladder is
    signal p, g: STD_LOGIC;
begin
    p <= a xor b;
    g <= a and b;
    s <= p xor cin;
    cout <= g or (p and cin);
end;

3.8 D Flip-Flop (Sequential Logic)

Basic D Flip-Flop

process (clk) begin
    if clk'event and clk='1' then
        q <= d;
    end if;
end process;

Resettable D Flip-Flop (Asynchronous Reset)

process (clk, reset) begin
    if reset = '1' then
        q <= "0000";
    elsif clk'event and clk='1' then
        q <= d;
    end if;
end process;

Enabled Register

process (ck) begin
    if (rising_edge(ck)) then
        if (enable = '1') then
            rt <= rin;
        end if;
    end if;
end process;
rout <= rt;

Finite State Machines (FSM) — Equations & Drawings

4.1 FSM Components

  • State register: stores current state, loads next state on clock edge
  • Next state logic: combinational logic computing S' from S and inputs
  • Output logic: combinational logic computing outputs from S (and inputs for Mealy)

4.2 Moore vs. Mealy

  • Moore FSM: outputs depend ONLY on current state (outputs labeled inside states)
  • Mealy FSM: outputs depend on current state AND inputs (notation on arcs: input/output)

4.3 FSM Design Procedure (Professor's Method)

Memorize This Procedure
  1. Identify inputs and outputs
  2. Sketch a state transition diagram
  3. Write a state transition table
  4. Select state encodings (binary or one-hot)
  5. Moore: rewrite encoded transition table + separate output table
    Mealy: rewrite combined transition & output table with encodings
  6. Write Boolean equations for next state and output logic
  7. Sketch the circuit schematic

4.6 State Encoding Options

  • Binary: minimum flip-flops (4 states → 2 bits: 00, 01, 10, 11)
  • One-hot: one flip-flop per state (4 states → 0001, 0010, 0100, 1000). More flip-flops but often simpler logic.

FSMD — Algorithms

5.1 What is an FSMD?

FSMD = Finite State Machine with Datapath. It starts from an algorithm (C-like pseudocode) and converts it into a hardware state machine that controls a custom datapath.

5.2 State Diagram Templates (Professor's Templates)

Memorize These 3 Templates

Assignment Statement

a = b  →  [State: a = b] → next statement

Each assignment gets its own state.

Loop (while)

while (cond) {     →    ┌──→ [C: cond?] ── !cond ──→ next statement
    loop-body           │        │ cond
}                       │        ↓
                        └── [loop-body states]
                                 │
                               [J: jump back to C]

Branch (if/else)

if (c1)            →  [C: check conditions]
    c1 stmts               /    |    \
else if (c2)            c1   !c1·c2  !c1·!c2
    c2 stmts             ↓     ↓      ↓
else                  [c1]   [c2]  [other]
    other stmts           \    |    /
                         [J: join] → next statement

5.3 Multiply Without Multiplier (FSMD Example)

// Algorithm
0: int x, y, z;
1: while (!go_i);
2: z = 0;
3: x = x_i;
4: y = y_i;
5: while (x != 0) {
6:     x = x - 1;
7:     z = z + y;
}
8: d_o = z;

Each line becomes a state; loops and branches use the templates above.

5.4 From FSMD to Controller + Datapath

Step 1 — Identify datapath components

  • All variables → registers (x, y, z)
  • All operations → functional units (subtractor, adder, comparator)
  • All external connections → ports (x_i, y_i, d_o, go_i)

Step 2 — Build the datapath

  • Connect ports, registers, and functional units
  • Add multiplexers wherever a register can be loaded from multiple sources
  • Add control signals: load enables (ldx, ldy, ldz), mux selects (selx, selz), output enables (ldd_o)

Step 3 — Create the controller FSM

5.5 GCD Example (Greatest Common Divisor)

0: int x, y;
1: while (1) {
2:   while (!go_i);
3:   x = x_i;
4:   y = y_i;
5:   while (x != y) {
6:     if (x < y)
7:       y = y - x;
      else
8:       x = x - y;
   }
9:   d_o = x;
}

GCD Datapath Components

  • Two registers: x, y
  • One output register: d
  • Two subtractors: (x − y) and (y − x)
  • Two comparators: (x ≠ y) and (x < y)
  • Two 2:1 multiplexers: x_sel chooses x_i vs. (x − y), y_sel chooses y_i vs. (y − x)

Controller Signals

Outputs: x_sel, y_sel, x_ld, y_ld, d_ld
Status inputs: go_i, x_neq_y, x_lt_y

5.6 Optimizing the FSMD (Professor's Rules)

Optimization Techniques
  1. Eliminate constant-transition states — State 1 (while(1)) always loops, remove it
  2. Merge state with its join state if no operation in between (merge 2 and 2-J)
  3. Merge independent assignments — states 3 and 4 can merge (x = x_i and y = y_i don't depend on each other)
  4. Merge condition checks — states 5 and 6 merge (state 6's transitions can evaluate in state 5)
  5. Eliminate unnecessary jump states — 5-J and 6-J removed (transitions originate from states 7, 8 directly)
  6. Eliminate redundant loop-back states — 1-J removed (state 9 goes directly to state 2)

Result: GCD goes from 13 states → 5 states

5.7 ROM-Based Controller Implementation

Instead of designing combinational logic with gates, store the entire state table in a ROM:

  • Address = current state bits + input signals
  • Data = next state bits + control signals

The professor demonstrated this with a VHDL ROM entity for the GCD controller: a 7-bit address produces a 9-bit output containing both next-state and control signal values.

  • Perform floating-point addition using the 8-step method
  • Identify special cases (zero, infinity, NaN)
  • Know single vs. double precision differences

  • Set up 3, 4, and 5-variable K-maps with proper Gray code ordering
  • Circle groups following the 5 rules
  • Extract minimized Boolean equations from circles
  • Handle don't cares correctly

VHDL — be able to:

  • Write an entity/architecture from scratch
  • Use concurrent signal assignments (and, or, xor, not, when/else)
  • Write sequential logic with process blocks (D flip-flop, resettable, enabled)
  • Use component declarations and port maps for structural design
  • Read and understand VHDL code given to you

FSM — be able to:

  • Draw state transition diagrams (Moore and Mealy)
  • Fill in state transition tables and output tables
  • Choose state encodings and fill in encoded tables
  • Derive next-state and output Boolean equations
  • Draw the complete schematic (next state logic → state register → output logic)

FSMD — be able to:

  • Convert an algorithm to an FSMD using the 3 templates (assignment, loop, branch)
  • Identify datapath components from the algorithm
  • Build a datapath diagram with registers, functional units, muxes, control signals
  • Create the controller state table mapping states/inputs to next states/control signals
  • Optimize an FSMD by merging/eliminating states
  • Understand ROM-based controller implementation
