1. The Big Picture: Language Hierarchy

Think of languages as categories of problems, and machines as the tools that solve them. Some problems are easy (you only need a simple tool), and some are hard (you need a powerful tool). The hierarchy goes from simple to powerful:

The Hierarchy (Least to Most Powerful)

Regular Languages ⊂ Context-Free Languages ⊂ Decidable Languages ⊂ Semidecidable Languages

Each level is strictly contained in the next. Every regular language is also context-free, every context-free language is also decidable, etc.

What "Recognizes" Each Type of Language?

Each language family has a machine that can recognize it and a grammar that can generate it:

Language TypeMachineGrammarExample
RegularFinite State Machine (FSM)Regular grammara*b* (any a's then any b's)
Context-FreePushdown Automaton (PDA)Context-free grammar (CFG)anbn (n a's then n b's)
DecidableTuring Machine (always halts)Unrestricted grammaranbncn
SemidecidableTuring Machine (may loop)Unrestricted grammarHalting problem

How to Tell Which Family a Language Belongs To

Ask yourself: what does a machine need to remember to accept this language?

  • Nothing beyond "where am I": Regular. An FSM with a fixed number of states is enough. Example: "strings that end in 'ab'" — you just need to remember the last two characters.
  • One counter or one "matching" task: Probably Context-Free. A stack (PDA) can handle one level of matching. Example: anbn — push a's, then pop one a for each b.
  • Two or more simultaneous matching tasks: NOT Context-Free. A stack cannot track two independent counts at the same time. Example: anbncn — you need to match a's to b's AND b's to c's simultaneously.
  • Finite language: ALWAYS regular. No matter how big, a finite set of strings can always be recognized by an FSM.

Key T/F Facts You Need to Know

Regular Language Closure: Regular languages are closed under union, intersection, complement, concatenation, Kleene star, difference, reverse, and letter substitution. "Closed under X" means: if you start with regular languages and apply operation X, you always get another regular language.
CFL Closure: Context-free languages are closed under union, concatenation, and Kleene star. They are NOT closed under complement and NOT closed under intersection.
DFSMs = NDFSMs in power (you can always convert an NDFSM to a DFSM). But DPDAs ≠ NPDAs — nondeterministic PDAs are strictly more powerful. Some CFLs (like wwR) have no deterministic PDA.
Turing Machines are NOT guaranteed to halt. There is no algorithm to force them to. FSMs always halt. PDAs might not halt but you can build equivalent ones that do.
Generator vs. Recognizer: A generator produces solutions (like a program that computes A+B). A recognizer checks if a proposed solution is correct (like checking if A+B=C). Most problems can be recast as decision problems (yes/no questions about strings).
Encoding: Almost anything can be represented as a string. <X> means "the string encoding of object X." This lets us turn any problem into a language recognition problem.

2. Context-Free Grammars: What They Are and How They Work

What is a CFG?

A context-free grammar (CFG) is a set of rules for generating strings. Think of it like a recipe for building strings character by character.

Formal Definition

A CFG G = (V, Σ, R, S) where:

  • V = all symbols (both terminals and nonterminals)
  • Σ = terminal symbols (the actual characters in your final string, like a, b, c)
  • R = rules (also called productions). Each rule has a single nonterminal on the left and anything on the right.
  • S = start symbol (a nonterminal where every derivation begins)

Terminals are the final characters (a, b, c, (, ), etc.). Nonterminals are working variables (S, A, B, T, etc.) that get replaced during derivation and disappear in the final string.

How Derivation Works

You start with the start symbol S and keep applying rules until only terminal symbols remain:

: Generating anbn

Grammar rules: S → aSb | ε

To generate "aabb":

S  ⇒  aSb         (applied S → aSb)
   ⇒  aaSbb       (applied S → aSb again)
   ⇒  aabb        (applied S → ε, S disappears)

The ⇒ symbol means "one derivation step." Each step, you pick one nonterminal and replace it using a rule.

Parse Trees

A parse tree shows the structure of a derivation. The root is S, each internal node is a nonterminal, and leaves are terminals. Parse trees are why we care about CFGs — they show us the structure of strings (like how an arithmetic expression is grouped).

Ambiguity

A grammar is ambiguous if some string has more than one parse tree. This is usually bad because it means the structure is not unique (e.g., does 2+3*4 mean (2+3)*4 or 2+(3*4)?).

A language is inherently ambiguous if EVERY grammar for it is ambiguous. Both "is this grammar ambiguous?" and "is this language inherently ambiguous?" are undecidable problems (no algorithm can always answer them).

Self-Embedding: Where CFGs Get Their Power

A grammar is self-embedding if a nonterminal can derive itself with nonempty strings on BOTH sides. Example: S → aSb is self-embedding (a on the left, b on the right of S).

Key theorem: If a grammar is NOT self-embedding, then its language is regular. If EVERY grammar for a language is self-embedding, then the language is NOT regular.

3. Simplifying CFGs and Converting to Chomsky Normal Form

This is a 10-point question on the exam. You will be given a CFG and must show your work for each step. The overall process is:

  1. Remove epsilon (ε) productions
  2. Remove unit productions
  3. Remove useless productions
  4. Convert to Chomsky Normal Form (removeMixed, then removeLong)

Step 1: Remove Epsilon Productions

An epsilon production is any rule like X → ε (a variable producing the empty string). These cause ambiguity, so we want to get rid of them.

Part A: Find All Nullable Variables

A variable is nullable if it can eventually produce ε. There are two ways:

  1. Directly nullable: There is a rule X → ε.
  2. Indirectly nullable: There is a rule X → ABC... where ALL of A, B, C are nullable.

Keep checking until you find no new nullable variables.

Part B: Add New Rules

For every rule that contains a nullable variable, add new versions where that nullable variable is "deleted" (replaced with ε). Do this for every combination of nullable variables in the rule.

Part C: Delete All X → ε Rules

: Remove Epsilon Productions

Given grammar:

S → aTa
T → ABC
A → aA | C
B → Bb | C
C → c | ε
Step 1: Find nullable variables

Round 1: C is nullable (C → ε is a rule). Nullable = {C}

Round 2: A is nullable (A → C, and C is nullable). B is nullable (B → C, and C is nullable). Nullable = {C, A, B}

Round 3: T is nullable (T → ABC, and A, B, C are ALL nullable). Nullable = {C, A, B, T}

Round 4: S is NOT nullable (S → aTa, but 'a' is a terminal and cannot be ε). No new variables. Done.

Step 2: Add new rules (substitute ε for nullable variables)

Go through each rule and create versions where nullable variables are removed:

S → aTa: T is nullable, so add S → aa

T → ABC: A, B, C are all nullable. Generate all combos of removing them:

  • Remove A: T → BC
  • Remove B: T → AC
  • Remove C: T → AB
  • Remove A,B: T → C
  • Remove A,C: T → B
  • Remove B,C: T → A
  • Remove A,B,C: T → ε (but we do NOT add this — we are getting rid of epsilon rules)

A → aA: A is nullable, so add A → a

A → C: C is nullable, so this would give A → ε. Don't add it (A is not the start symbol).

B → Bb: B is nullable, so add B → b

B → C: C is nullable, would give B → ε. Don't add.

C → c: No nullable variables in RHS. No new rule.

Step 3: Delete all X → ε rules

Remove C → ε. Final result:

S → aTa | aa
T → ABC | BC | AC | AB | A | B | C
A → aA | C | a
B → Bb | C | b
C → c

Step 2: Remove Unit Productions

A unit production is a rule where the right side is a single nonterminal, like A → B. These are unnecessary indirection.

The Algorithm

  1. Pick any unit production X → Y.
  2. Remove it.
  3. Look at all remaining rules for Y (like Y → abc, Y → DE). For each one, add X → abc, X → DE, etc. But do NOT add any rule that was already removed.
  4. Repeat until no unit productions remain.

B's rules are: B → b. So add A → b.

Steps 4-5: Convert to Chomsky Normal Form

What is CNF?

In Chomsky Normal Form, every rule looks like one of these two forms:

  • A → BC (exactly two nonterminals)
  • A → a (exactly one terminal)

No mixing terminals with nonterminals in the same rule. No rules with more than 2 symbols on the right.

removeMixed: Fix Rules That Mix Terminals and Nonterminals

If a rule has length > 1 on the right side AND contains a terminal, replace each terminal with a new variable.

: removeMixed
Before:                     After:
A → a             A → a              (length 1, leave alone)
A → aB            A → TaB            (replaced 'a' with Ta)
A → BaC           A → BTaC           (replaced 'a' with Ta)
A → BbC           A → BTbC           (replaced 'b' with Tb)

Add new rules:
Ta → a
Tb → b

removeLong: Break Rules With More Than 2 Symbols

If a rule has more than 2 nonterminals on the right, chain it into pairs using new variables.

: removeLong
Before:                     After:
A → BCDE                  A  → BM2
                            M2 → CM3
                            M3 → DE

The idea: take the first symbol, pair it with a new variable that represents "the rest." Repeat until each rule has exactly 2 symbols.

4. Pushdown Automata: What They Are

A PDA is like an FSM but with a stack attached — an unlimited scratch pad where you can only access the top element. This extra memory is exactly what lets PDAs handle context-free languages that FSMs cannot.

Definition: PDA

M = (K, Σ, Γ, Δ, s, A) where:

  • K = set of states
  • Σ = input alphabet (the characters you read)
  • Γ = stack alphabet (the characters you can push/pop)
  • s = start state
  • A = set of accepting states
  • Δ = transitions: ((state, input_or_ε, what_to_pop), (new_state, what_to_push))

How the Stack Works

The stack is like a pile of plates. You can only see/remove the top plate (pop), and you can only add new plates on top (push). Written left to right, the leftmost character is the top.

If the stack contains "cab" (c on top), and you push "xy", the stack becomes "xycab" (x is now on top).

Reading Transition Labels

Transitions are written as: input / pop / push

  • input: what character to consume from the input (or ε to consume nothing)
  • pop: what to remove from the top of the stack (or ε to pop nothing)
  • push: what to add to the top of the stack (or ε to push nothing)

Accepting a String

A PDA accepts a string w if there exists at least one sequence of transitions that:

  1. Starts in the start state with empty stack
  2. Reads all of w (consumes every character)
  3. Ends in an accepting state with empty stack

Since PDAs are nondeterministic, there may be multiple paths. If ANY path accepts, the string is accepted.

A PDA rejects w only if ALL paths fail (dead end, non-accepting state, or stack not empty). If even one path accepts, the string is accepted.

6. Directly Constructing a PDA for a Language

This is a 10-point question. Dr. Stringfellow says: "DO NOT try to generate the grammar first." Build the PDA directly from the language description.

The General Strategy

  1. Identify the "phases" of the input. What comes first? What comes second?
  2. Use the stack to count/remember. Push during one phase, pop during another.
  3. Design states for each phase.
  4. Handle acceptance: Accept when input is consumed AND stack is empty AND in accepting state.
: PDA for anbn (n ≥ 0)

Phases: First read a's, then read b's. Number of a's must equal number of b's.

State 1 (start, accepting): Reading a's phase

Transition: read 'a', pop nothing, push 'a'. Stay in State 1.

This pushes one 'a' onto the stack for each 'a' in the input.

State 1 → State 2: Switch to reading b's

Transition: read 'b', pop 'a', push nothing. Go to State 2.

When we see the first 'b', start popping.

State 2: Reading b's phase

Transition: read 'b', pop 'a', push nothing. Stay in State 2.

Each 'b' removes one 'a' from the stack.

Acceptance

State 1 is accepting (handles n=0, empty string).

State 2 accepts when input is done AND stack is empty (equal counts).

Written formally:

States: {q1, q2}, Start: q1, Accept: {q1, q2}
Transitions:
  ((q1, a, ε), (q1, a))    -- read a, push a
  ((q1, b, a), (q2, ε))    -- read b, pop a
  ((q2, b, a), (q2, ε))    -- read b, pop a
: PDA for {w ∈ {a,b}* : #a(w) = #b(w)}

Key insight: Unlike anbn, the a's and b's can come in any order. The stack needs to track the "imbalance."

The idea

If we have more a's than b's so far, the stack has a's in it.

If we have more b's than a's so far, the stack has b's in it.

If they are equal, the stack is empty.

Transitions (single state q1, start and accepting)
Read 'a', stack top is 'b' → pop 'b' (they cancel out)
Read 'a', stack top is 'a' or empty → push 'a'
Read 'b', stack top is 'a' → pop 'a' (they cancel out)
Read 'b', stack top is 'b' or empty → push 'b'

Accept when input consumed and stack empty (counts are equal).

: PDA for {ambn : m ≠ n, m,n > 0}

Key insight from Dr. Stringfellow: Start with the equal case and handle the two mismatch cases.

Base: match a's and b's

State 1: read a, push a. State 2: read b, pop a.

Case 1: More a's than b's (m > n)

Input is done but stack still has a's. Go to accepting State 3, pop remaining a's.

Transition: (ε / a / ε) in a loop at State 3.

Case 2: More b's than a's (m < n)

Stack is empty but input still has b's. Go to accepting State 4, consume remaining b's.

Transition: (b / ε / ε) in a loop at State 4.

The tricky part: detecting bottom of stack and end of input

Detect bottom of stack: Push a special marker '#' before starting. When you see '#', you know the stack is "empty."

Detect end of input: Use nondeterminism — at any point during b-reading, nondeterministically guess "this is the last b" and try to transition.

7. GNF Grammar to Top-Down PDA

This is a 5-point question. You are given a grammar already in Greibach Normal Form and must build the corresponding PDA.

What is Greibach Normal Form (GNF)?

Every rule looks like: A → aα where 'a' is a single terminal and α is a string of zero or more nonterminals.

Example: S → aSA | a (both start with a terminal).

The Construction (Memorize This)

GNF to PDA Algorithm

PDA has 3 states: q0 (start), q1 (working), qf (accept). Stack alphabet = grammar variables. Use 'z' as stack bottom marker.

  1. Startup: δ(q0, ε, z) = {(q1, Sz)} — push start symbol S on top of z.
  2. For each rule A → aX1X2...Xn:
    δ(q1, a, A) includes (q1, X1X2...Xn) — read 'a', pop A, push X1...Xn (X1 on top).
  3. For each rule A → a (no variables):
    δ(q1, a, A) includes (q1, ε) — read 'a', pop A, push nothing.
  4. Finish: δ(q1, ε, z) = {(qf, ε)} — if stack only has z (everything matched), accept.

8. Turing Machines: What They Are

A Turing Machine (TM) is the most powerful computational model we study. It has an infinite tape (memory), a read/write head that can move left or right, and a finite control (states).

Definition: Turing Machine

M = (Q, Σ, Γ, δ, q0, F) where:

  • Q = finite set of states
  • Σ = input alphabet (no blank symbol)
  • Γ = tape alphabet (includes blank □ and all of Σ)
  • q0 = initial state
  • F = halting/final states
  • δ: (Q - F) × Γ → Q × Γ × {L, R}

δ is a function (deterministic). Given a non-halting state and tape symbol, it tells you: new state, symbol to write, direction to move.

Key Differences from FSMs and PDAs

  • The tape is infinite in both directions.
  • The head can read AND write (FSMs only read; PDAs read input and read/write a stack).
  • The head can move both left and right (FSMs/PDAs only move right through input).
  • TMs are NOT guaranteed to halt. They can loop forever.
  • TMs can compute functions (produce output), not just accept/reject.

How a Transition Works

δ(q0, a) = (q1, b, R) means: "In state q0, reading 'a' on the tape: write 'b' (replacing 'a'), move head Right, go to state q1."

Deciding vs. Semideciding

  • M decides L: M halts on EVERY input. Accepts w if w ∈ L. Rejects w if w ∉ L. Language is in class D.
  • M semidecides L: M accepts w if w ∈ L. If w ∉ L, M may reject OR loop forever. Language is in class SD.

9. Tracing a Turing Machine

This is a 10-point question. Given a TM's transition table or diagram, trace its execution on a given input and determine what it does.

How to Write Configurations

A configuration shows the complete state of the machine at one moment: (state, tape contents with head position). The head is scanning the character immediately after the state label in the tape string.

: Trace the "Replace a's with b's" TM

Given: Q = {q0, q1}, Σ = {a, b}, F = {q1}

δ(q0, a) = (q0, b, R)   -- see 'a': replace with 'b', move right, stay in q0
δ(q0, b) = (q0, b, R)   -- see 'b': leave as 'b', move right, stay in q0
δ(q0, □) = (q1, □, L)   -- see blank: don't write, move left, go to q1 (HALT)

Trace input "aab":

StepStateTapeHead PositionAction
0q0□ a a b □^ on first 'a'Start
1q0□ b a b □^ on second 'a'Wrote b, moved R
2q0□ b b b □^ on 'b'Wrote b, moved R
3q0□ b b b □^ on last 'b'Left b, moved R
4q1□ b b b □^ on last 'b'Hit □, moved L, HALTED

What does this TM do? It replaces all a's with b's, leaving b's unchanged. The output tape contains all b's.

: TM from Sample Final (Turing Machine that copies 1's)

From the Sample Final Q2: Design a TM that copies strings of 1's. Input: □1111□, Output: □11111111□

The intuitive process given:

  1. Replace every 1 by a marker (like #).
  2. Find the rightmost # and replace it with 1.
  3. Travel to the right end of the current nonblank region and create a 1 there.
  4. Repeat steps 2 and 3 until there are no more #'s.

This doubles the string of 1's by marking each original 1, then expanding each mark into an additional copy at the end.

10. Building a Turing Machine

This is a 10-point question (extra credit for shorthand notation).

The Long Notation (Transition Table)

Write out every transition as: δ(state, tape_char) = (new_state, write_char, direction).

Common TM Design Patterns

Pattern 1: "Scan and Mark" (for matching problems)

Used for languages like anbncn or wcw.

  1. Find an unmarked 'a'. Mark it (replace with special symbol like '$').
  2. Scan right to find an unmarked 'b'. Mark it.
  3. Scan right to find an unmarked 'c'. Mark it.
  4. Scan all the way back to the start.
  5. Repeat. If you run out of a's, check that b's and c's are also gone.
  6. If everything matches: accept. If mismatch at any point: reject.

Pattern 2: "Copy" (for duplication)

To copy w: for each character in w, mark it, scan to the end, write a copy, scan back.

Shorthand Notation (Extra Credit)

Basic Shorthand Machines
  • a, b, c, □ — writes that symbol on the current square, then halts.
  • R — moves head right one square, halts.
  • L — moves head left one square, halts.
  • y — halts and accepts.
  • n — halts and rejects.
Combining Machines
  • M1 M2 — run M1, then when it halts, immediately run M2 (no condition).
  • M1 —a→ M2 — run M1, when it halts look at the tape: if current symbol is 'a', go to M2.
  • M1 —a→ M2, —b→ M3 — branch: if 'a' go to M2, if 'b' go to M3.
Useful Macro Machines
  • R□ — scan right until you find a blank.
  • L□ — scan left until you find a blank.
  • R¬□ — scan right until you find a NON-blank.
  • L¬□ — scan left until you find a NON-blank.
  • Ra — scan right until you find 'a'.
  • La — scan left until you find 'a'.
: TM for anbncn in Shorthand

11. Pumping Lemma and Closure Properties (T/F Prep)

Pumping Lemma for Regular Languages

The Theorem (in plain English)

If a language L is regular, then there is some number k such that every string in L that is at least k characters long can be "pumped." That means you can split it into three parts x, y, z where:

  • The string is w = xyz
  • |xy| ≤ k (x and y together are in the first k characters)
  • y is not empty
  • You can repeat y any number of times (including 0) and the result is still in L

How to Use It to Prove a Language is NOT Regular

: Prove anbn is Not Regular
Step 1: Assume L is regular

Then there exists some k from the Pumping Lemma.

Step 2: Choose a string w in L with |w| ≥ k

Let w = akbk. This is in L (equal a's and b's) and has length 2k ≥ k.

Step 3: Show that no valid split works

Since |xy| ≤ k, both x and y must fall entirely within the first k characters, which are all a's. So y = ap for some p ≥ 1.

Now pump with q = 2 (repeat y twice): xy2z = ak+pbk.

This string has more a's than b's, so it is NOT in L. Contradiction.

Step 4: Conclude

Since we found a string that cannot be pumped, L is not regular.

Using Closure Properties Instead of Pumping

Sometimes pumping is hard. Closure properties offer an easier path:

: Prove {w ∈ {a,b}* : #a(w) = #b(w)} is Not Regular

If L were regular, then L ∩ a*b* would also be regular (regular languages are closed under intersection, and a*b* is regular).

But L ∩ a*b* = {anbn : n ≥ 0}, which we already proved is not regular.

Contradiction. So L is not regular.

: Prove {aibj : i ≠ j} is Not Regular

If L is regular, then the complement of L is also regular (closure under complement).

complement(L) ∩ a*b* = {anbn} ∪ {strings not of form a*b*}.

Actually, even simpler: complement(L) includes all strings with equal a's and b's in a*b* form, which is anbn. Since complement(L) ∩ a*b* = anbn, and anbn is not regular, complement(L) cannot be regular. So L cannot be regular either.

Dr. Stringfellow's tips for pumping:
  • Choose w that is "barely" in L and makes the first k characters as uniform as possible.
  • Try q = 0 (pump out) or q = 2 (pump in) first.
  • If direct pumping is awkward, try closure properties instead.
