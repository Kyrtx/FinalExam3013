1. Pointers

Core Concepts

A pointer is a variable that stores the address of another variable. Three operators to know:

Operator Name What It Does
& Address-of Gets the memory address of a variable
* (declaration) Pointer declaration Declares a pointer variable: int *ptr;
* (usage) Dereference / Indirection Accesses the value at the address the pointer holds

Basic Example (pr10-02 style)

int x = 25;
int *ptr = &x;       // ptr now holds the address of x

cout << x;           // 25 (the value)
cout << &x;          // 0x7fff... (address of x)
cout << ptr;          // same address as &x
cout << *ptr;         // 25 (dereference — get value at address)
cout << &ptr;         // address of the pointer itself (different)
On the exam (Test 1 Question 1), given an array and a pointer number that points to the very beginning, you must evaluate expressions like *number, *(number+5), (*number+5), (*number+2), etc. The parentheses matter enormously.

Pointers and Arrays

An array name is essentially a constant pointer to the first element. 

int numbers[] = {10, 20, 30, 40, 50};

*numbers        → 10          // value at index 0
*(numbers + 1)  → 20          // value at index 1
(*numbers + 1)  → 11          // value at index 0, THEN add 1
(numbers + 1)   → address of index 1
&numbers[1]     → same address as (numbers + 1)
*(numbers + i) and numbers[i] are interchangeable. A pointer can use subscript notation: ptr[i] works just like *(ptr + i).

Pointer Arithmetic

When you do ptr++ or ptr + 1, the pointer moves forward by the size of the data type it points to (e.g., 4 bytes for int, 8 bytes for double). 

int set[] = {5, 10, 15, 20, 25, 30, 35, 40};
int *numPtr = set;

// Forward traversal
for (int i = 0; i < 8; i++) {
    cout << *numPtr << " ";
    numPtr++;               // moves to next int
}

// Backward traversal
for (int i = 0; i < 8; i++) {
    numPtr--;
    cout << *numPtr << " ";
}

Pointers as Function Parameters

void getNumber(int *input) {
    cout << "Enter an integer: ";
    cin >> *input;           // stores into the variable pointed to
}

void doubleValue(int *val) {
    *val *= 2;               // modifies original variable
}

int main() {
    int number;
    getNumber(&number);      // pass ADDRESS
    doubleValue(&number);    // pass ADDRESS
    cout << number;          // modified!
}

Dynamic Memory Allocation

// Allocate
double *sales = new double[numDays];

// Use it like a normal array
sales[0] = 100.50;

// ALWAYS free when done
delete [] sales;
sales = 0;           // good practice: set to null

Multi-Level Pointers (Triple Pointers)

int x = 25;
int *ptr1 = &x;         // pointer to int
int **ptr2 = &ptr1;      // pointer to pointer to int
int ***ptr3 = &ptr2;     // pointer to pointer to pointer to int

***ptr3 → 25            // dereference three times to get x

3. Recursion (Factorial)

Factorial: n! = n × (n-1)!

int factorial(int n)
{
    if (n == 0)
        return 1;          // base case
    return n * factorial(n - 1);  // recursive case
}

This earned full marks + 3 bonus on Test 1 Q2. The key is: base case returns 1 when n == 0, recursive case multiplies n by factorial(n-1).

4. Complexity Analysis — Loop Analysis

The professor requires a 3-part structure: (1) Step by Step Analysis for Inner Loop, (2) Step by Step Analysis for Outer Loop, (3) Step by Step Analysis for Entire Code — Combine. Box final and partial answers.

Example 1 (HM5 Q1): i doubles, j increments

for (int i = 1; i < n; i *= 2) {
    for (int j = 0; j < n; j++) {
        counter = counter + 1;
    }
}
STEP 1: Inner Loop Analysis
j starts at 0, adds 1 each time, stops at n.
So inner loop runs exactly n times.
Operation inside: counter = counter + 1 → one operation, so one constant.
Work done: c · n
f_inner = c · n ← box this
STEP 2: Outer Loop Analysis
i starts at 1 and doubles each step. Stops when i ≥ n.
Sequence: i = 1, 2, 4, 8, ... → i = 2k
Stops when 2k = n → k = log₂(n)
f_outer = log₂(n) ← box this
STEP 3: Combine (Total Work)
Total Work = (outer loop) · (inner loop)
= log₂(n) · (c · n)
= log₂(n) · c · n
Drop constant (insignificant):
O(n · log₂(n)) ← box this

Example 2 (HM5 Q2): Both loops multiply

for (int i = 1; i < n; i = 4*i) {
    for (int j = 1; j < n; j = j*3) {
        counter = counter + 1;
    }
}
Outer Loop: i = 1, 4, 16, 64... → i = 4k. Stops at 4k = n.
log₄(4k) = log₄(n) → k = log₄(n)
Convert to log₂ using change of base: log₄(n) = log₂(n) / log₂(4) = log₂(n) / 2
Take out n from constant: (1/2) · log₂(n)
f_outer = (1/2) · log₂(n)
Inner Loop: j = 1, 3, 9, 27... → j = 3k. Stops at 3k = n.
log₃(3k) = log₃(n) → k = log₃(n)
Convert: log₃(n) = log₂(n) / log₂(3) ≈ log₂(n) / 1.585
Take out n from constant: (1/log₂(3)) · log₂(n) = c · log₂(n)
f_inner = c · log₂(n)
Combine:
Total Work = f_outer · f_inner = (1/2) · log₂(n) · c · log₂(n)
= (1/(2·log₂(3))) · [log₂(n)]²
Drop constant:
O([log₂(n)]²) ← box this

7. Master Theorem — Professor's Method

This is the professor's #1 tested method. Quiz 9 (100/100), Test 2 Q1 (30.33), Test 2 Q2 (33.33). Must follow exactly: extract a, b, K, p → Condition 1 (compare a vs bK) → identify case → Condition 2 (check p) → apply formula → simplify.

Setup: The General Form

T(n) = a · T(n/b) + nK · logp(n)

Extract four values: a (number of recursive calls), b (division factor), K (exponent on n), p (exponent on log, default 0 if no log term).

Condition 1: Compare a vs bK

Comparison Case
a < bK Case 1
a = bK Case 2
a > bK Case 3

Condition 2: Check p for Case 2

Once you know it's Case 2, check the value of p:

p value Condition Met?
p > -1 Yes → use Case 2 formula
p = -1 Special subcase
p < -1 Different subcase

The Formulas

Case 1 (a < bK): T(n) = Θ(nK · logp(n))

Case 2 (a = bK), p > -1: T(n) = Θ(nlog_b(a) · log(p+1)(n))

Case 3 (a > bK): T(n) = Θ(nlog_b(a))

Worked Example 1 (Quiz 9 — 100/100)

T(n) = 2T(n/4) + n0.51

Extract values: a = 2, b = 4, K = 0.51, p = 0
Condition 1: Compare a vs bK
bK = 40.51 = 2.027918...
a = 2, bK = 2.027918
2 < 2.027918 → a < bK → Case 1
Condition 2: p = 0, and p > -1 ✓ (but for Case 1 just check p ≥ 0)
Apply Case 1 formula:
T(n) = Θ(nK · logp(n))
= Θ(n0.51 · log0(n))
= Θ(n0.51 · 1)
T(n) = Θ(n0.51)

Worked Example 2 (Test 2 Q1)

T(n) = 2T(n/2) + n·log₂(n)

Extract: a = 2, b = 2, K = 1, p = 1
Condition 1: bK = 21 = 2. a = 2 = bK → Case 2
Condition 2: p = 1 → p > -1 ✓
Apply Case 2:
T(n) = Θ(nlog_b(a) · log(p+1)(n))
= Θ(nlog₂(2) · log(1+1)(n))
= Θ(n1 · log²(n))
T(n) = Θ(n · log²(n))

8. Iterative Method (Repeated Substitution)

ITERATIVE METHOD ONLY. Must show: (a) 3 expansions, (b) running time, (c) complexity. This is the method from Quiz 8 (100/100).

General Pattern

Given a recurrence like T(n) = { c if n=1; d + T(n-1) if n > 1 }

Step A: Show 3+ Expansions
T(n) = d + T(n-1)
T(n-1) = d + T(n-2) → sub in: T(n) = 2d + T(n-2)
T(n-2) = d + T(n-3) → sub in: T(n) = 3d + T(n-3)
T(n-3) = d + T(n-4) → sub in: T(n) = 4d + T(n-4)
Step B: Generalize
T(n) = k·d + T(n-k)
Step C: Find Base Case
Base case: n = 1, so n - k = 1 → k = n - 1
Step D: Substitute k and Simplify
T(n) = (n-1)·d + T(n-(n-1))
= (n-1)·d + T(1)
= (n-1)·d + c
= nd - d + c
= nd + (c - d) ← constants
Running Time: nd + (c - d)
Complexity: Θ(n)

Another Form: T(n) = T(n-1) + c + d (Quiz 8 — crossed out attempt)

The approach is the same — just substitute repeatedly, generalize to k, find k from the base case, and simplify. The professor crossed out the attempt that went T(n) = T(n-1) + (c+d), sub T(n-1) = T(n-2) + (c+d), etc. and ended at T(n) = Θ(n). The correct version showed all steps cleanly.

9. Recursion Tree Method

The professor's tree method uses a specific table format: Level | R-call | # Nodes | Tree | Row Sum. You must fill out this table, set up the summation [Eq1], find the upper bound, and solve the summation.

The 4-Step Process

STEP 1: Build the Tree & Its Components
Create the table with columns: Level, R-call, # Nodes, Tree (visual), Row Sum.
At each level, identify what the recursive call looks like, how many nodes exist, what work each node does, and what the total (row sum) is.
STEP 2: Generalize the R-call Expression
Find the pattern: T(n) → T(n/2) → T(n/4) → T(n/8) → ... → T(n/2k)
So T(n/2k) is the general expression.
STEP 3: When Do We Stop?
Stop at the base case: n/2k = 1 → n = 2k → k = log₂(n)
This is the upper bound for the summation.
STEP 4: Analyze & Solve the Summation [Eq1]
Set up: Σ (row sum expression) from i=0 to k.
Solve using summation rules or geometric series formula.

Example #1 (Balanced): T(n) = 2T(n/2) + 4n

Level R-call # Nodes Row Sum
0 T(n) 1 4n
1 T(n/2) 2 4n
2 T(n/4) 4 4n
3 T(n/8) 8 4n
... ... ... ...

Every row sums to 4n → [Eq1]: Σ 4n from i=0 to log₂(n)

Since 4n doesn't depend on i, factor it out: 4n · Σ 1 from i=0 to log₂(n)

Split: 4n · [1 + Σ 1 from i=1 to log₂(n)] = 4n · [1 + log₂(n)]

= 4n + 4n·log₂(n) = Running Time

T(n) = Θ(n·log₂(n))

Example #2 (Binary Search): T(n) = T(n/2) + e

Level R-call Tree Row Sum
0 T(n) e e
1 T(n/2) e e
2 T(n/4) e e
... ... e e

Only 1 node per level (no branching). Stop: n/2i = 1 → i = log₂(n).

Σ e from i=0 to log₂(n) = e · [1 + log₂(n)] = e + e·log₂(n)

T(n) = Θ(log₂(n))

Example #3 (Geometric Series): T(n) = 2T(n/2) + n²

Row sums: n²/2⁰, n²/2¹, n²/2², ... → geometric series where ratio r = 1/2.

General expression: Σ n²/2i from i=0 to log₂(n) = n² · Σ (1/2i)

This is a geometric series with a₀ = 1, r = 1/2, m = log₂(n) terms.

Geometric Series Formula:
α = a₀ · (1 - rm) / (1 - r)
where a₀ = first term, r = ratio (computed as a_{i+1}/a_i), m = number of elements

α = 1 · (1 - (1/2)log₂(n)) / (1 - 1/2) = 2 · (1 - (1/2)log₂(n)) = 2 - 2·(1/2)log₂(n)

Running Time = n² · α = 2n² - 2n²·(1/2)log₂(n)

To determine complexity, justify which side dominates. Choose n = 2²⁰:

A = 2·(2²⁰)² = 2⁴¹, B = 2·(2²⁰)²·(1/2)²⁰ = 2⁴¹·(1/2²⁰) = 2²¹

A = 2⁴¹ ≫ B = 2²¹, so A dominates.

T(n) = Θ(n²)

Example #4 (Unbalanced): T(n) = T(n/3) + T(2n/3) + n

Tree is NOT balanced (different branch sizes). Row sum at every level is n. The longest branch (right-most, the 2n/3 side) determines the upper bound.

Right path: n → 2n/3 → (2/3)²n → (2/3)³n → ... → (2/3)kn

Stops when (2/3)k·n = 1 → n = (3/2)k → k = log_{3/2}(n)

Sum: Σ n from i=0 to log_{3/2}(n) = n · [1 + log_{3/2}(n)]

T(n) has complexity: n·log_{3/2}(n), which is Θ(n·log(n))

10. Merge Sort

How It Works

Divide and conquer: keep splitting the array in half until you have individual elements, then merge sorted subarrays back together.

Key Formula for Split Point

q = ⌊(p + r) / 2⌋

Where p = left index, r = right index. Always floor the result.

Tracing Merge Sort (Professor's Context Method)

The professor traces merge sort using contexts (ctx1, ctx2, ...). Each recursive call creates a new context. When the base case is hit (p ≥ r, i.e., one element), return to the previous context.

Given A = {6, 5, 4, 3}:

ctx1: merge-sort(A, 0, 3) → q = ⌊(0+3)/2⌋ = 1
  calls merge-sort(A, 0, 1) → ctx2

ctx2: merge-sort(A, 0, 1) → q = ⌊(0+1)/2⌋ = 0
  calls merge-sort(A, 0, 0) → ctx3

ctx3: merge-sort(A, 0, 0) → p=0, r=0 → p ≥ r? NO (0 < 0 is false). Actually p < r? (0 < 0) NO → return to ctx2

ctx4: from ctx2: merge-sort(A, 1, 1) → return (base case)

ctx5: from ctx2: MERGE(A, 0, 0, 1) → merge subarrays → A becomes [5, 6, ...]

...continues similarly for the right half, then final merge...

The Merge Process

Given Merge(A, p, q, r):

n1 = q - p + 1 (size of left subarray), n2 = r - q (size of right subarray)

Copy into temporary arrays L and R. Then compare elements from L and R, placing the smaller one back into A.

Comparisons Per Level

Level # of Comparisons For n=8
0 n - 20 = n - 1 7
1 n - 21 = n - 2 6
2 n - 22 = n - 4 4
3 n - 23 = n - 8 0

Complexity Derivation

Number of levels: Array of size n divides by 2 each time → n/2i = 1 → i = log₂(n) → levels = log₂(n) + 1
Work per level during merging: c · n (at most n comparisons per level)
Complexity: (Number of Levels) × (Work per Level) = (log₂(n) + 1) × cn = cn·log₂(n) + cn
After removing non-dominant terms:
Merge Sort = O(n · log₂(n))

Time: O(n log n)   |   Space: O(n)

13. Graph Algorithms — Fundamentals

Basic Definitions

A graph G = (V, E) where V = set of vertices (nodes), E = set of edges.

The cardinality of edges is bounded by the Cartesian product of vertices: |E| ≤ |V × V|, so |E| = O(V²).

Dense vs Sparse

Type Condition Use
Dense |E| ~ |V²| (lots of edges) Adjacency Matrix
Sparse |E| ~ |V| (few edges) Adjacency List

Graph Variations

Undirected: edges have no direction (drawn as lines, NO arrows). Edges are bidirectional.

Directed: edges go from one vertex to another (drawn as arrows). Has in-degree and out-degree.

Weighted: edges have a cost/weight associated with them.

Representation #1: Adjacency Matrix

A is an n×n matrix where a_{ij} = 1 if edge (i,j) ∈ E, and 0 otherwise.

For undirected graphs: the matrix is symmetric.

Storage: Θ(V²)   |   Edge lookup: O(1)

Representation #2: Adjacency List

For each vertex, keep a list of adjacent vertices. Represented as a linked list.

Storage: Θ(V + E)   |   Edge lookup: O(|Adj(u)|)

Out-Degree

out-degree(u) = |Adj(u)| = number of outgoing edges from node u.

For directed graphs: Σ out-degree(u) = |E|

For undirected graphs: Σ degree(u) = 2|E|

Comparison Table

Property Adjacency Matrix Adjacency List
Memory Θ(V²) Θ(V + E)
Is (u,v) ∈ E? O(1) O(|Adj(u)|) — NOT O(n)
Good for Dense graphs Sparse graphs

14. BFS (Breadth-First Search)

General Idea

(a) Find the shortest distance reachable from a starting vertex S in the graph.

(b) Explore all reachable nodes from S and estimate shortest distance from S to all others.

BFS Pseudocode

BFS(s):  // assume adjacency list representation
1)  For each u ∈ V - {s}       // every node except start
2)      do d[u] ← inf          // distance = infinity (not visited)
3)  d[s] ← 0                   // start node distance = 0
4)  Q ← {s}                    // enqueue start node
5)  While Q ≠ ∅                // while queue not empty
6)      do remove u from Q     // dequeue
7)      for each v ∈ Adj[u]    // expand neighbors
8)          do if d[v] = inf   // not visited yet
9)              then d[v] ← d[u] + 1  // distance = parent + 1
10)             put v onto Q   // enqueue
Key points from the professor's annotations: Line 8 checks d[v] = inf, which means "you have not visited/examined this node." Line 9: d[v] = d[u] + 1 means: distance of node v = distance to reach ancestor u + 1. BFS uses a queue (FIFO).

BFS vs Dijkstra

BFS: shortest path in unweighted graphs (all edges weight = 1).

Dijkstra: shortest path in weighted graphs. BFS is essentially Dijkstra with all edge weights equal to 1.

15. DFS (Depth-First Search)

Key Properties

Goal: explore every vertex and edge. Uses adjacency list representation.

Each node u tracks: d[u] = discovery time, f[u] = finish time, color[u] = white/gray/black.

Color Meaning
White Not yet discovered
Gray Discovered, still being explored (in the "stack")
Black Fully explored (all neighbors finished)

DFS Pseudocode

DFS(G):
1)  For each u ∈ V[G]
2)      do color[u] ← white
3)  time ← 0
4)  For each u ∈ V[G]
5)      do if color[u] = white
6)          then DFS-VISIT(u)

DFS-VISIT(u):
1)  color[u] ← gray
2)  d[u] ← time ← time + 1
3)  for each v ∈ Adj[u]
4)      do if color[v] = white
5)          then DFS-VISIT(v)
6)  color[u] ← black
7)  f[u] ← time ← time + 1

Edge Classification

Edge Type Description Color Transition
Tree edge Encounter a new node gray → white
Back edge Descendant to ancestor gray → gray
Forward edge Ancestor to descendant (non-tree) gray → black
Cross edge Between subtrees/trees gray → black

DFS Example

For a graph with vertices {S, A, B, C, D, E, F, G}, starting from S: 

S: d=1,  f=12
A: d=2,  f=7
B: d=3,  f=4
C: d=8,  f=11
D: d=5,  f=6
E: d=13, f=16
G: d=9,  f=10
F: d=14, f=15

Edge labels: T = Tree, B = Back, F = Forward, C = Cross. Look at the color of the destination node when the edge is explored.

16. Dijkstra's Shortest Path Algorithm

General Idea

1. Let distance of start vertex from start = 0.
2. Let distance of all other vertices from start = INFINITY.

REPEAT:
3. Visit the unvisited vertex with the smallest known distance from start.
4. For the current vertex, examine its unvisited neighbors.
5. For each neighbor, calculate distance from start. If calculated distance is smaller than the known distance, update the shortest distance.
5b. Update previous vertex for each updated distance.
6. Add current vertex to visited list and remove it from unvisited list.

UNTIL ALL VERTICES ARE VISITED.
Key terms the professor underlines/bolds in the Dijkstra handout: "smallest known distance", "unvisited neighbors", "smaller than", "remove it from the unvisited list." These are the critical decision points in the algorithm.
